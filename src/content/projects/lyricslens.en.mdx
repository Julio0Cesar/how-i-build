Lyrics that follow the song, in a window that sits above whatever is on screen,
on a desktop where the window manager is allowed to say no.

Twelve releases in five days, which is what happens when the hard parts are
discovered by measurement instead of guessed at.

<Entry title="Rust owns the clock" date="2026-08-02" />

Every lyrics overlay that burns CPU makes the same mistake: a `setInterval` in
the frontend asking the backend where the song is, several times a second.
Nothing about that is wrong until you notice the fan.

<Decision>
The backend emits an event only when something changes, plus one light
synchronisation tick per second. The frontend interpolates between ticks with
`requestAnimationFrame`. Karaoke at 60fps with CPU near zero.
</Decision>

<Tradeoffs>
- The frontend holds a copy of the timeline and can drift between ticks
- Any state that matters has to travel as an event, which is more plumbing than a poll
- Debugging means reading two clocks instead of one
</Tradeoffs>

<Entry title="On Wayland, a window cannot place itself" date="2026-08-03" />

Tauri offers `alwaysOnTop`, and it does nothing here. That is not a bug: on
Wayland the client is not allowed to position itself or raise itself above
others. The compositor decides, by protocol design.

The spike measured what actually happens on Hyprland:

- `alwaysOnTop: true` — a no-op; the window opened tiled, ignoring the size it asked for
- `hyprctl setfloating` plus `pin` — works, and exact geometry is accepted
- `transparent` and `decorations: false` — both work
- Surviving another window going fullscreen — not as a window; yes as a layer

<Decision>
Two strategies. By default a floating window with compositor rules, which covers
normal use. Optionally a `wlr-layer-shell` surface, which survives fullscreen —
it stops being a window at all, disappearing from `hyprctl clients` and
appearing in `hyprctl layers` at the overlay level.
</Decision>

Three details the implementation has to get right, each found the hard way:
`init_layer_shell` must run before the window is realised, because the surface
type is fixed at that point in the protocol — which is why the window is born
invisible and why the option needs a restart. Exclusive zone `-1`, or the
compositor shrinks every other window to make room, as it would for a taskbar.
`KeyboardMode::None`, or the layer steals the keyboard from whatever is focused.

The layer mode is off by default because a layer cannot be dragged. Position
comes from preferences instead of the mouse — a trade, not an improvement.

<Entry title="Anchoring the clock to an edge" date="2026-08-04" />

The lyric line changed up to a second late. A second is the difference between
karaoke and subtitles.

<Decision>
Anchor the clock to the edge of the position report rather than to its value.
Measured: the error fell from ±1000ms to ±71ms, at no cost worth naming.
</Decision>

<Tradeoffs>
- It relies on the player reporting position at a steady cadence, which not all of them do
- The remaining ±71ms is the floor of what MPRIS reports, not something the code can improve
</Tradeoffs>

<Entry title="Two windows instead of one" date="2026-08-04" />

The settings screen and the overlay are the same application, and one of them is
meant to sit on screen for hours.

<Decision>
Separate windows. The overlay never loads the CSS or JavaScript of the settings
interface, which is what keeps its memory footprint small.
</Decision>

<Tradeoffs>
- State shared between them has to cross a process boundary rather than a prop
- Two windows to keep visually consistent, and two to test
</Tradeoffs>

<Entry title="Deferring translation without deferring the schema" date="2026-08-05" />

Translated lyrics were wanted and were not going to be built yet.

<Decision>
Reserve the field in the cache schema now, fill it later. The feature is
deferred; the migration is avoided.
</Decision>

<Tradeoffs>
- A column that holds nothing, which reads as an oversight to anyone who does not know why
- If the eventual shape differs from the reserved one, the migration comes back anyway
</Tradeoffs>
